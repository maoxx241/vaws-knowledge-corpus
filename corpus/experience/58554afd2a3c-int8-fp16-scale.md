# 融合 INT8 量化时保留了先舍入 FP16 scale 的顺序

2026-09-09 至 09-10，将 vLLM Ascend 查询张量的 abs/amax、scale 与 INT8 量化合为一个 Triton kernel 时，最容易误改的是数值顺序。原路径先把 scale 转成 FP16，再用它扩回 FP32 做除法；直接使用未舍入的 FP32 scale 虽然更精细，却改变了原结果。实现因此保留先舍入、最小 scale 限制、偶数舍入与对称截断。

测试构造了正负半整数、全零行、FP16 次正规数和 scale 溢出等边界，逐项要求 INT8 与 FP16 scale 精确一致，另覆盖非连续输入和改变输入后的图回放。A3 上的原始结果为 43 passed，记录的环境包括 torch_npu 2.10 开发版与 Triton 3.2。执行布局按物理向量核数限制 grid，连续分块，并让不同核的 FP16 scale 写入按完整 32 字节组划分。

这次通过证明了所列矩阵的融合数值与回放行为。初版仍有随行数变化的 constexpr 分块参数，43 项测试没有验证所有新长度预热后都不再编译；后续编译变体问题需要独立处理。微秒级算子计时也没有包含编译、捕获与整网服务，因此不把一次融合通过写成线上性能已经完成验收。
