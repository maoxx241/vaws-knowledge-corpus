# 审计 pool 清零时，用预填 NaN 区分有效输出与未写行

2026-09-10，一次 vLLM Ascend 持久输出 buffer 审计讨论能否删除 `out.zero_()`。所查 pool 只写部分有效行，未完成行和 padding 行会保留 `torch.empty` 的旧内容。整块 tensor 不一致既不能直接证明有害，也不能据此宣布清零可删，关键是哪些行会被后续消费者读取或写入缓存。

调查先用 NaN 和常数 17 预填输出，再切换起始位置、请求长度和有效行。18 组真实 NPU 记录显示，状态与有效输出完全一致，已执行的后续 norm、投影和量化在有效行上也一致；同时明确记录无效行仍保留原内容。改变输入和有效行后的图回放继续通过，因此测试没有把“尾部碰巧为零”当作正确条件。

证据边界决定了这次只形成审计结果。RoPE 和最终 scatter 仅检查了源码，当时加载库还缺相关执行符号，未完成完整消费者链的设备验证；生产 `out.zero_()` 没有删除。后续若实施优化，仍需证明无效行不会被这些未验环节消费，并同步修改测试契约。此次局部通过不能变成通用的免清零规则，也不能把未写行中的 NaN 自动认作整网根因。
