# 阅读 C4/C128 实现时，纠正了只看压缩主分支的模型理解

2026 年 8 月的一次 DeepSeek V4 结构调查中，C128 被误解成只有某一种 attention 分支，而“压缩历史 + SWA”的说明又容易被理解为两次 attention 输出直接相加。调查改为从模型创建 Compressor、Indexer 的条件，一直追到 attention 调用的参数构造。

原始源码显示，这些层先准备原始 SWA KV，压缩比大于 1 时再加入压缩 KV，C4 还传入 Indexer 选择的稀疏索引；C128 不传这份索引，最后由同一次 attention 调用消费。由此区分了两个概念：C4/C128 描述长程压缩方式，并没有概括整层全部输入；参数组合也不等于输出张量直接相加。

继续核对 Compressor 后，又把 C4 的重叠窗口与非重叠压缩分开。描述“每若干 token 生成一个压缩 KV”时，还要说清推进步长和参与窗口，否则会在 state cache、残留 token 或压缩边界的推导中混淆二者。

这次工作是公共实现的阅读与解释，没有改动模型，也没有运行设备精度测试。历史讨论中的固定窗口数值未当作所有配置的通用常量保存。可复用的经验是：遇到模型名称或图示产生歧义，直接追 constructor 条件、传给算子的 KV/索引以及最终调用次数，用实际数据流校正概念，而不是从命名推导行为。
