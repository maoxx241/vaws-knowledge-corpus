# 同步消融和百分之百采信都没有证明状态污染已修复

2026-08-04 至 08-08，Kimi K3 长前缀历史请求污染的调查多次尝试 blocking H2D、device synchronize 与 completion fence。源码检查确实发现需要分别考虑 CPU metadata 复用、异步拷贝完成、Mamba state copy 和调度发布，但某次加同步后短请求恢复，不能直接判定根因或宣称根治。

回读后续原始结果时，有一轮 miss 正常，hit 返回 HTTP 200 和预期输出长度，却以 token 0 开头且输出检查失败。同一轮计数为 128 次 draft、896 个 draft token、896 个 accepted token，七个位置各接受 128 次：数值上是 100% draft 接收率、含 bonus 的平均长度 8，但请求仍然错误。指标自洽只能证明统计口径一致。

该轮还缺少完整 token/text hash 与严格历史控制对齐，报告本身将 `experiment_valid` 置为 false。因此它既不能证明某个确定的竞态，也不能作为指定历史故障的完整复现；足以撤回的是“同步后已解决”和“高采信即正确”的过强表述。继续调查时需要把真实输出、有限值、状态地址与同条件对照合在一起，已被后续失败推翻的同步补丁只保留为尝试记录。
