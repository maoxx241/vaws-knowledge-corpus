# 合并重复 metadata 构建时，把物理地址留在缓存组内

2026-09-10，优化一个 vLLM Ascend 衍生模型的 metadata 热路径时，发现 KV-group 循环反复计算同批请求的计数、长度与位置变换。直接把整个结果移到循环外并不安全：同批请求在不同缓存组使用不同物理 block，部分状态也由各组独立推进。

修改分开了每次构建共享的 batch 数据和组内数据。请求统计、公共长度及相同条件下的算子 metadata 复用；slot mapping 与环形状态仍在所属组内生成。同时删除没有消费者的坐标计算，将依赖组地址的计算留在缓存未命中分支。验证使用不同 block ID，并在图回放中改变长度、物理块与 idle 输入，避免“共享后数值相等”只是输入碰巧相同。

四项真实 NPU 用例通过，覆盖同步构建和 metadata stream，只比较算子定义的有效 payload，排除保留区。原始 16 请求局部对照中，构建加设备同步约从 19.118 ms 降到 4.382 ms；这不包含整网服务，也不证明异步重叠或 TPOT 收益。另有三项回归失败在未修改基线上复现，不能称全仓通过。本篇保留的是减少批内重复工作时，如何同时验证跨组地址隔离的经历。
